# SEC069 Ruby false positive on English prose interpolation

**Date:** 2026-10-13 19:39
**Files:** sentinel/rules/code.py, tests/test_v050.py
**Severity:** medium

## Problem

SEC069 (shell command with Ruby interpolation) fired on ordinary
interpolated strings that merely contained the English words "system"
or "exec":

```ruby
puts "system status #{x}"      # SEC069 — false positive
logger.info "exec time #{t}"   # SEC069 — false positive
```

Found during `/aif-review` of the v0.5.0/v0.6.0 commits and confirmed
with a live probe before fixing.

## Root Cause

The regex used an **optional** parenthesis and a loose trailing match:

```
(?:system|exec)\s*\(?[^\n]*?#\{
```

Because `\(?` made the call-parenthesis skippable and `[^\n]*?#\{`
only required "something then `#{` on the same line", any occurrence
of the bare word `system`/`exec` (even inside a double-quoted string,
where the lookbehind `(?<![\w.])` still passes because `"` is not a
word char) followed later by string interpolation matched the rule.
The same shape affected the Open3/IO.popen alternative.

Wrong assumption at author time: "system + later #{ on the line can
only be a shell call". In prose strings it happens constantly.

## Solution

Require a real call shape before allowing the interpolation match:

- call form: `system("...#{...}")` → `\s*(?:\([^\n]*?#\{`
- command-string form: `system "ls #{dir}"` → `|\s+["'][^\n]*?#\{`

Applied identically to the `Open3.capture2?` / `IO.popen` alternative.
Backtick alternative left unchanged (backticks are always shell
execution in Ruby — no prose false-positive class).

Regression tests added in tests/test_v050.py:
- prose "system"/"exec" strings must NOT fire
- paren form, string form, backtick, Open3, argv-safe still correct

## Prevention

- When a rule pattern ends in a loose `X...Y` pair (word + later
  metacharacter), check whether the first word can appear as **plain
  English inside string literals** — probe with a prose string before
  shipping.
- For "dangerous function + argument shape" rules, bind the function
  name to an actual call/string delimiter (`\(` or `\s+["']`), never
  an optional paren plus free-form trailing regex.
- Language-word rules (system/exec/eval/popen) always deserve a
  same-line prose-FP probe in the pre-ship probe script.
